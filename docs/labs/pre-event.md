# 事前イベント：業務定義を伝え、処理の流れを調べる

同じ分析 Agent に業務定義を伝えると回答がどう変わるか、回答の裏側にどんな処理があるかを、実際に操作して確かめます。「この数字を信頼してよいか」「回答までに何が起きたか」を、自分の言葉で説明することが目標です。

基本課題では BigQuery Agents の会話画面で自分で質問し、結果と生成 SQL を確認します。業務定義は Knowledge Catalog の画面で直接編集します。Cloud Shell のコマンドは、業務定義を書くエントリとエージェントの準備、保存した定義をエージェントへ渡すことに使います。SQL を自分で書く必要はありません。早く終わった方や、さらに調べたい方は、各実習の手順書の後半にある「任意 Challenge」で、ほかの質問や条件も試してみてください。

## 最初に：環境を準備する

[共通の事前準備](preparation.md)を最後まで済ませてください。準備ページの[「手順 4．準備を終えて次へ進む」](preparation.md#手順-4準備を終えて次へ進む)にある 2 項目がすべて確認できれば完了です。準備で止まった場合は、主催者の案内した窓口に相談してください。

## 実習 1：その「売上」、同じ意味で話していますか？

「7 月の注文を 8 月に返金したら、どちらの月の売上から引く？」を考えてから、BigQuery Agents で Agent に質問します。Knowledge Catalog のエントリで OKF 形式の業務定義を編集し、3 つの Agent へ同じ質問を送ります。さらに、集計 View を使った場合の違いを見ていきます。

[実習 1 の手順](lab1.md)に沿って、次の点を確認してください。

- 定義を伝える前と後で、回答の前提はどう変わったか。
- 数字だけでなく、期間・返金の扱い・生成 SQL を確認できたか。
- 自社なら、誰が業務定義を決め、結果を検証するか。

さらに試したい方は、同じ質問をもう一度送ったときに回答がどう変わるかを、手順書の最後の任意 Challenge で確かめられます。

## 実習 2：回答の裏側で何が起きている？

1 回の質問の裏側をたどります。[実習 2 の手順](lab2.md)に沿って教材の Web 画面で Root Agent を実行し、Cloud Trace と BigQuery のジョブ履歴で、処理の順・所要時間・トークン・エラーを確認します。**設定を変えて比べるのは #3 です。**

実習 2 の最後（手順 4）では、性質の違う質問に変えて、処理の流れがどう変わるかを予想してから確かめます。

## 終了時に

判断シートに、観測から分かったことと、自社で曖昧になっている用語を 1 つ残してください。自社の定義案はメモに書き、実習で編集した Knowledge Catalog の定義はそのまま残します。

Summit にも参加する方は、教材フォルダとクラウド環境を残し、[バックアップ](backup.md)を取ります。Summit では今回の代表例を短く振り返った後、品質・時間・費用の比較へ進みます。
