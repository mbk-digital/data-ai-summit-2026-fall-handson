# 共通の事前準備：実習環境を用意する

このページでは、教材データ・実行環境・実行履歴の記録設定を準備します。準備が終わったら、参加する回の手順へ進みます。

コマンドはコードブロックごとにコピーして実行し、各操作の完了を確認してから次へ進んでください。同じ環境でこの準備をすでに済ませた方は、[README の進行表](../../README.md#2参加する回の手順を進める)から続きの実習へ進めます。

このページのコマンドは、どれも `cd ~/summit-workshop && …` の形で、教材フォルダへ移動してから実行します。README と別の場所に教材を取得した場合は、コマンドの `~/summit-workshop` をそのフォルダに置き換えます。

## 手順 1．実習用の環境を用意する

実習では、Python 環境を **uv** というツールで管理します。uv は Cloud Shell に最初から入っています。教材のコマンドは毎回 `uv run --locked` から始め、その都度 uv が必要なライブラリを揃えます。Cloud Shell を開き直しても、環境を再有効化する操作は不要です。

必要なライブラリを取得します。時間がかかる場合があるため、完了までお待ちください。イベントの前に済ませておくこともできます。

```sh
cd ~/summit-workshop && uv sync --locked
```

**確認：** `Installed ... packages`（すでに取得済みの場合はより短い表示）と表示され、入力待ちに戻れば完了です。下の折りたたみにないエラーが出た場合は、最後のエラー文を主催者へ伝えてください。

<details>
<summary><code>uv: command not found</code>、または <code>Required uv version</code> を含むエラーが出た場合</summary>

uv が見つからないか、教材に必要な版より古い状態です。新しい uv を導入します。

```sh
curl -LsSf https://astral.sh/uv/install.sh | sh
```

`commands are shadowed` と表示された場合も、続けて次を実行してください。導入した uv を、現在のターミナルで優先して使えるようにします。

```sh
export PATH="$HOME/.local/bin:$PATH"
```

この操作は、正常なら何も表示しません。バージョンを確認します。

```sh
uv --version
```

`uv 0.12.2` 以降のバージョンが表示されたら、上の `uv sync --locked` をもう一度実行してください。

</details>

Cloud Shell のホームフォルダは保持されるため、この取得は最初の 1 回だけです。

## 手順 2．Project を設定し、教材データを用意する

このハンズオンでは、参加者自身の個人用 Google Cloud Project を使います。この準備で、BigQuery の 5 テーブルと View、AI の実行履歴を残す設定を作ります。

### 実行前に確認すること

コマンドを実行する前に、今開いている Google Cloud コンソールの画面で次の 3 点を確認してください。

1. **実習用 Project を選択して ID を控える:** コンソール上部のプロジェクト選択画面を開き、実習で使う Project の「ID」を確認してコピーします（表示用の「プロジェクト名」や数字の「プロジェクト番号」ではなく、英数字の「ID」を使います。Project 自体が未作成の場合は [Project の作成手順](https://docs.cloud.google.com/resource-manager/docs/creating-managing-projects?hl=ja) に沿って作成してください）。
2. **その Project のオーナーであることを確認する:** コンソールのメニューから「IAM と管理」→「IAM」を開き、自分のアカウントのロールに「オーナー」があることを確認します。自分で作成した Project なら付与済みです。
3. **その Project の課金を確認する:** コンソールのメニューから「課金」を開き、対象 Project に有効な請求先アカウントが紐付いていることを確認します。利用したサービスの料金は、このアカウントへ計上されます。紐付いていない場合や、確認の方法が分からない場合は、[プロジェクトの課金の有効化、無効化、変更](https://docs.cloud.google.com/billing/docs/how-to/modify-project?hl=ja)を参照してください。

> 上の確認で権限エラーが出た場合は、その画面と対象 Project を主催者へ伝え、解消してから進んでください。

### 準備コマンドを実行する

次の 1 つのコマンドで、Project 設定の保存・API 有効化・教材データの構築・権限診断・記録設定をまとめて行います。

> [!IMPORTANT]
> **コマンド内の `YOUR_PROJECT_ID` を、先ほど控えた自分の Project ID に書き換えてから実行してください。**
> `YOUR_PROJECT_ID` のまま実行すると、書き換えるよう求めるエラーが表示されて停止します。この段階ではまだクラウドを変更しません。

```sh
cd ~/summit-workshop && uv run --locked python3 -m workshop.setup --project YOUR_PROJECT_ID
```

**確認の流れ：**
1. 実行すると、対象 Project・アカウントと、これから行う 5 つの工程が表示され、実行の確認を求められます。
   - ※ 実行時に「Cloud Shell の承認」ダイアログが表示されたら、**実習用アカウントであることを確認して「承認」を押します**（[認証の公式説明](https://docs.cloud.google.com/shell/docs/auth)も参照できます）。
2. **表示された Project ID とアカウントが自分のものであることを確認し、`y` を入力して Enter を押します。**（違う場合は Enter を押して中止してください。この時点ではまだクラウドを変更していません）
3. 工程ごとに `[1/5] …… 完了` のように表示されます。最後に 3 項目が `OK` と表示され、`事前準備が完了しました。` で終われば成功です。

途中で止まった場合は、原因を解消してから**同じコマンドをもう一度実行**してください。完了した工程は作り直さず、残りから再開します。準備済みの場合は現在の状態を確認し、問題がなければ `準備はできています。` と表示します。追加の作業を実行する場合は、先に内容を表示して確認を求めます。

> **「課金が有効か確認できませんでした」と表示された場合：**
> 課金状態を読み取れなかった表示です。「課金」画面で課金が有効か確認し、不明なら主催者へ相談してください。

### BigQuery Console で作成結果を確認する

コマンドの最後に表示された **BigQuery（テーブルと View）** の URL を開きます。Cloud Shell では、文字を選ぶとコピーされます。ブラウザの新しいタブに貼り付けて開きます。以後の実習で AI が参照するデータを、自分の目で確かめます。

BigQuery のホーム画面が開いたら、左の一覧で自分の Project ID →「データセット」→ `ec_workshop` の順に開きます。ホーム画面の「最近」の一覧には、別の Project の `ec_workshop` が並ぶことがあるので、そこからは開きません。

**自分の Project の `ec_workshop` に、5 つのテーブル（`campaigns`、`order_items`、`orders`、`products`、`refunds`）と `v_revenue_events` View があれば完了です。** データは全部で 28 行だけなので、実習 1 では手計算でも答えを確かめられます。

<details>
<summary>見つからないとき・もっと見たいとき</summary>

- ブラウザで複数の Google アカウントにログインしていると、Console が教材で使うのとは別のアカウントで開くことがあります。画面右上のアカウントのアイコンで、教材で使うアカウントになっているか確かめます。
- 画面上部には Project の表示名が出るので、ID とは違って見えることがあります。左側の一覧に出る ID が、コマンドの出力の `対象Project` と同じか確かめます。違う Project が出ていたら、画面上部の Project の名前を押し、一覧の ID の列で自分の Project を探して切り替えます。
- 各テーブルの「詳細」で行数（順に 2、9、9、3、5 行）、「プレビュー」で中身の架空の EC データが見られます。

</details>

## 手順 3．AI の実行履歴が残ることを確認する

手順 2 のコマンドの最後に表示された **BigQuery Agents（Monitoring）** の URL を開きます。

手順 2 のコマンドは、AI の実行履歴を残す設定（Google Cloud の標準 Observability）まで有効にしています。AI が回答するまでに実行した SQL、各処理にかかった時間、モデルのトークン使用量が記録され、実習 2・3 で使います。

<details>
<summary>「Monitoring を有効化」のボタンが出たとき</summary>

「Monitoring を有効化」を押し、「すべて有効にする」→「次へ」→「閉じる」と進めてから、画面を再読み込みします。有効にするのは準備コマンドで有効化済みの API と同じもので、準備で作った記録設定は変わりません。「ユーザーのアクセス権限」は、Project のオーナーなら操作不要です。

</details>

**Monitoring の画面が開けば完了です。** まだ質問していないので、グラフが空だったり、エラーのような表示が出たりしても正常です。

<details>
<summary>うまくいかないとき</summary>

- 新しい Project では、「トレース ストレージが初期化されました」という案内と、各欄に「バックエンドでエラーが発生しました」「… `_AllSpans` does not exist」と出ることがあります。まだ記録がないための表示で、異常ではありません。
- 自分の Project で開いているか迷ったら、画面上部の Project の名前を押し、一覧の ID の列で確かめます。
- 開けない場合は、準備コマンドをもう一度実行し、`未完` と表示された行と対象 Project を主催者へ伝えてください。

</details>

## 手順 4．準備を終えて次へ進む

次の 2 つが終わっていることを確認してください。

1. 準備コマンドが `事前準備が完了しました。` で終わり（準備の後にもう一度実行した場合は `準備はできています。`）、**BigQuery Console で 5 テーブルと View を自分の目で確認した**。
2. **BigQuery Agents の Monitoring 画面を開けた**（中身は空でよい）。

コマンドの完了表示だけでなく、**この 2 つの Console 確認まで必ず行ってから**次へ進んでください。

[実習 1](lab1.md) の「手順 1．業務定義を伝える前の Agent に質問する」から始めます。Summit から参加する方向けの準備手順は後日公開します。

全体の順序は[README の進行表](../../README.md#2参加する回の手順を進める)で確認できます。
