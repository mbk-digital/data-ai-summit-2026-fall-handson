# 予測・観察・判断シート

各欄に 1 行ずつ、紙か手元のメモに書いてください。読むだけでも構いません。書いた内容は Agent へ送られず、採点にも使いません。

ファイルに残す場合は、Cloud Shell Editor で `participant/decision-notes.md` など、まだない名前で保存します。`participant/` フォルダは、教材の更新（`git pull`）で上書きされません。この文書や実行記録を書き換える必要はありません。

## #1：どの定義で判断する？

**実行前の予測**：7 月の注文を 8 月に返金したら、どちらの月の売上から引きますか。そう考えた理由も一言。

- 私の予測：＿＿＿＿
- 画面で確認した違い、または違いが出なかった点：＿＿＿＿
- この会社の分析で採用する定義と、確認した根拠：＿＿＿＿
- 自社なら定義を決める担当／データに反映する担当／検証する担当：＿＿＿＿

教材の会社は、返金を返金した月で計上します。自分の予測と違っても間違いではありません。会社の取り決めと回答の前提を合わせられることがゴールです。基本課題は全員同じ定義で比較し、自社の案はメモに分けます。

## #2：その回答の裏側で、何が起きている？

**手順 3 の前の予測**：手順 2 で見た「Data Agent 呼び出し」は 2 回でした。どちらかが無駄だとしたら、それは何のための依頼だと思いますか。いちばん時間がかかるのはどこだと思いますか。

- 私の予測と理由：＿＿＿＿
- 実際の処理の順と、いちばん時間を使った箇所：＿＿＿＿
- モデルが使ったトークンと、エラーの有無：＿＿＿＿
- 手順 4 で選んだ質問（A／B）と、③への依頼の本数・差額の計算の予想：＿＿＿＿
- 予想と Cloud Trace の結果の違い：＿＿＿＿
- 観測から分かったこと／観測だけでは分からなかったこと：＿＿＿＿

本番で同じ Agent を運用するとして、何が見えていれば障害の原因を説明できるかを考えてください。設定を変えて速さや費用を比べるのは #3 で行います。

## 持ち帰り：自社で曖昧になっている用語を 1 つ

数値や社内データを入力せず、定義の案だけを手元のメモに書きます。例えば「売上」以外にも「有効顧客」「解約」「対応完了」などを選べます。

- 用語名：＿＿＿＿
- 何を含め、何を除くか：＿＿＿＿
- いつの出来事として扱うか：＿＿＿＿
- 定義を決める担当と、例外を確認する相手：＿＿＿＿
- 正しいか確認するための質問 1 つ：＿＿＿＿

これは業務定義の下書きです。Catalog への登録や自社データ接続を完了した意味ではありません。実際の利用には、データとの対応・権限・集計方法・検証を別途整えます。

## 印刷して使う場合

主催者が配布する「予測・観察・判断シート」の A4・1 枚版を使います。印刷版は各欄に短い言葉を手書きする形式で、詳しい説明はこの GitHub 版を参照します。長い理由は裏面か手元のメモに続けて構いません。印刷は A4 縦・100%を基本とし、実機で端が欠ける場合は印刷可能領域に合わせます。
