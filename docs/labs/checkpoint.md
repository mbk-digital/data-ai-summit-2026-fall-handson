# Summit の開始確認：分析環境を用意・確認する

実習 3 で使う 3 つ（分析データ・業務定義・分析エージェント「EC分析 ③」）が自分の Google Cloud プロジェクトに揃っているかを確かめます。分析データは共通の事前準備で作ってあるので、Summit から初めて参加する方は、ここで業務定義と分析エージェントを作ります。できれば当日より前に実行して、`開始できます。` と表示されるところまで進めます。当日より前に済ませた方は、当日の最初にもう一度実行します（環境がまだ使えるかを確かめます。1 分ほどで終わり、環境に変更がなければ何も作りません）。当日その場で準備した方は、もう一度実行する必要はありません。

実習 1・2 に参加していない方も、ここで完成した業務定義を使って準備できます。AI エージェントに質問する操作はありません。

## 自分に合う手順を選ぶ

| あなたの状況 | 進む場所 |
|---|---|
| Summit から初めて参加する | [共通の事前準備](preparation.md) → 下の「手順 1．開始確認を実行する」 |
| 事前イベントと同じ Project・教材フォルダで続ける | 主催者の案内に沿って[教材を更新する](../cloud-shell-workflow.md#教材を更新する) → 下の「手順 1．開始確認を実行する」 |
| 準備を済ませた Project を、取得し直した教材フォルダや別のフォルダで使う | 「手順 1．開始確認を実行する」の最初の折りたたみを先に開く |

▶ の折りたたみは、見出しに書かれた方・場面のときだけ開きます。該当しなければ、開かずに次へ進みます。

> **共通の事前準備がまだの方は、先に[共通の事前準備](preparation.md)を済ませてください。** 下のコマンドは、準備で取得した教材フォルダと、準備で設定した Project を使います。

## 手順 1．開始確認を実行する

<details>
<summary>準備を済ませた Project を、別の教材フォルダで使う方だけ</summary>

先に自分の Project を設定します。別のフォルダへ移した方は、このページのコマンドにある `~/summit-workshop` も、そのフォルダに置き換えます。共通の事前準備を済ませた方や、同じフォルダで続ける方は設定済みなので不要です。

```sh
cd ~/summit-workshop && uv run --locked python3 -m workshop configure --project YOUR_PROJECT_ID --bigquery-location US --data-agent-location us --catalog-location us
```

教材の記録（管理台帳）は教材フォルダの中にあります。下の開始確認で「要相談（教材の記録がありません…）」と出たら、バックアップから戻す必要があります。講師に声をかけてください。

</details>

Cloud Shell で、次のコマンドを実行します。

```sh
cd ~/summit-workshop && uv run --locked python3 -m workshop.checkpoint start
```

**確認：** 最初の行の `開始確認：Project …` が、自分の Project ID であること。違う場合は、このあと `続けますか？` と聞かれても `y` を入力せず、講師に声をかけてください。

確かめるのに 1 分ほどかかります。その後、4 つのまとまりの状態が表示されます（例）。

```text
  分析データ（BigQuery）              OK
  業務定義（Knowledge Catalog）       OK
  分析エージェント「EC分析 ③」        OK
  実行の準備（API・権限・観測）       OK
```

**最後に表示される文**で、次の操作を決めます。

| 最後に表示される文 | 次の操作 |
|---|---|
| `開始できます。` | 「手順 2．Console で確かめる」へ。ただし、同じ環境で Console の確認を一度済ませていて、今回は作成・修復なし（`続けますか？` と聞かれず）に表示された方は、Console の確認は不要です。当日は[実習 3](lab3.md)へ進みます。当日より前なら、準備はここまでです |
| `続けますか？ [y/N]:` | 下の「足りないものを作る」へ。ただし、準備を済ませた方が当日にもう一度実行してこの表示が出た場合は、何も入力せず講師に声をかけてください（前回から環境が変わっています） |
| `開始できません。何も変更していません。` | 「手順 4．止まったとき」へ |
| `作成の途中で止まりました。` | 「手順 4．止まったとき」へ |

この確認では、データを確かめるために BigQuery の利用料金が少しかかります。

### 足りないものを作る

「これから作ります」「これから直します」があるときは、作る前に確認を求められます。Summit から初めて参加する方は、この表示になるのが普通です。

```text
この Project（participant-project）に、「これから作ります」のものを用意します。
変更する参加者のファイルは、先に退避します。BigQuery の利用料金が少しかかります。
続けますか？ [y/N]:
```

表示された Project ID が自分のものであることをもう一度確かめて、`y` を入力し、Enter を押します。作成には数分かかります。`n` を入力すると、何も変更せずに終わります。

作り終わると、もう一度確かめて、同じ 4 つのまとまりを表示します。`開始できます。` が出たら「手順 2．Console で確かめる」へ進みます。

> 「要相談」「確認できませんでした」があるときは、確認を求めずに止まります。教材の記録と実際のリソースを照らし合わせる必要があるので、講師を呼んでください。

<details>
<summary>何を作るのか、自分の業務定義はどうなるのか（読むのは任意）</summary>

作成は、参加者ファイル、分析データ（BigQuery）、業務定義（Knowledge Catalog）、分析エージェント、観測の設定の順に進みます。

- 自分で完成させた業務定義（`participant/semantics.txt`）はそのまま使い、標準の定義で上書きしません。
- 業務定義がない場合や、#1 の雛形のままの場合は、Knowledge Catalog に保存された業務定義を使います。それもなければ、#1 の手順書の置き換えと同じ標準の定義を使います。変更する前のファイルは `artifacts/checkpoints/` の中に退避します。
- 別の用途のデータや、内容が合わないリソースは上書きしません。
- `y` を入力した後、作り始める前にもう一度状態を確かめます。その間に設定・ファイル・クラウドが変わっていたら、何も変更せずに止まります。

</details>

<details>
<summary>「注意：BigQuery のジョブ情報を読む権限が確認できませんでした」と出たとき</summary>

実習は始められます。#3 で費用のうち BigQuery の分が「未算出」になる場合があります。

</details>

## 手順 2．Console で確かめる

> 同じ環境で Console の確認を一度済ませていて、今回は作成・修復なし（`続けますか？` と聞かれず）に `開始できます。` と表示された方は、Console の確認は不要です。当日は[実習 3](lab3.md)へ進みます。当日より前なら、準備はここまでです。

`開始できます。` の後に、3 つのリンクが表示されます。順に開き、**同じ Project で**次を確かめます。

1. **分析データ**（BigQuery）：`ec_workshop` に 5 つのテーブルと `v_revenue_events` View がある。
2. **業務定義**（Knowledge Catalog）：リンク先は、教材が使う業務定義のエントリです。**概要**に書かれた文章が、分析エージェントに渡す業務定義の本文です。`[[` が残っていない（返金の計上日が `refunded_date（返金日）`、返品で戻す原価が `recovered_cost_jpy（実際に回収できた原価）` になっている）ことを確かめます。
3. **分析エージェント**（BigQuery Agents）：リンク先のエージェント カタログで「EC分析 ③ 業務定義あり＋集計View」を押します。右側の「詳細」の「ナレッジソース」に `v_revenue_events` があることを確かめます。この確認では「エージェントを編集」は押しません。同じ名前が複数ある場合や見つからない場合は、講師に声をかけてください。

- **当日より前に実行した場合**：準備はここまでです。当日は、最初にもう一度「手順 1．開始確認を実行する」を実行してから、実習 3 の質問の送信を始めます。作成・修復なしに `開始できます。` と表示されれば、この Console での確認はもう一度行う必要はありません。
- **当日に実行した場合**：この確認まで終えたら[実習 3](lab3.md)へ進みます。

<details>
<summary>開始確認が確かめている内容（読むのは任意）</summary>

| まとまり | 揃っているべきもの |
|---|---|
| 分析データ | BigQuery の 5 テーブルと `v_revenue_events` View。データと View の定義が教材と一致していること |
| 業務定義 | 完成した `participant/semantics.txt` と、Knowledge Catalog の業務定義 |
| 分析エージェント | 業務定義と集計 View を使う Data Agent（③） |
| 実行の準備 | 必要な API と権限、ADK、標準 Observability の設定 |

どのまとまりでも、教材が作ったリソースの記録（管理台帳）と、実際のリソースが一致していることも確かめます。詳しい結果は `artifacts/checkpoints/diagnosis.json` に保存されます。

`開始できます。` は、実習を始める条件が揃っていることを確かめた意味です。モデルの実行が成功することや、Cloud Trace への反映までは保証しません。

この確認は、API の有効化やライブラリの取得を代わりに行いません。不足は共通の事前準備で解消します。API を有効にした直後は、反映を待ってから実行し直してください。

Checkpoint は BigQuery Graph を作成・復元・削除しません。

</details>

## 手順 3．バックアップを残す（環境を後日も使う方）

実習を終えて、後日も同じ環境で続ける方（事前イベントの後に Summit へ続ける方を含む）は、教材フォルダの外にバックアップを残します。Summit では今日の環境をそのまま使います。その間に教材フォルダが消えたり、教材を取得し直したりしても、このファイルがあれば開始確認で戻せます。

```sh
cd ~/summit-workshop && uv run --locked python3 -m workshop.checkpoint backup --file "$HOME/summit-checkpoint-backup.json"
```

**確認：** `バックアップを保存しました：` の後ろに保存先とファイル数が表示されれば完了です。参加者の設定・業務定義・管理台帳が入ります。

> Project やリソースの識別子を含む個人用のファイルです。**GitHub などに公開しないでください。** 同じ名前のファイルがあると上書きしないので、取り直すときは別の名前にします。

バックアップから戻す操作は、講師と一緒に行います。教材フォルダや管理台帳は削除せず、実行したコマンドと表示された文を講師に伝えてください。

## 手順 4．止まったとき

次のどれかになったら、**そこで作業を止めて、講師に声をかけてください。** 自分で直そうとしないでください。

- `開始できません。何も変更していません。` と表示された（「要相談」「確認できませんでした」がある）
- `作成の途中で止まりました。` と表示された
- `作成は終わりましたが、まだ開始できません。` と表示された
- 権限や課金のエラーが出た

> `作成を始める前に止まりました。何も変更していません。` と表示された場合は、もう一度同じコマンドを実行します。同じ表示になったら、講師に声をかけてください。

講師には、次を伝えます。

1. 画面に表示された 4 つのまとまりと、最後の文
2. 対象 Project ID
3. `artifacts/checkpoints/diagnosis.json` があること（中身を送る必要はありません）

認証トークンや秘密鍵は送らないでください。

> **教材フォルダと、その中の `artifacts/` は、片付けが終わるまで消したり編集したりしないでください。** 消すと復旧できなくなります。
