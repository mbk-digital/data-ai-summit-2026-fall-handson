# 全体の地図：どこを操作し、裏で何が動き、どこで結果を見るか

3 つの実習は、**同じ EC 分析 Agent を題材に、見る範囲を広げていきます。**

| 実習 | 見る範囲 |
|---|---|
| **#1** | 分析 Agent **単体**。同じ質問に、業務定義と集計 View の有無で回答がどう変わるか |
| **#2** | その分析 Agent を**呼び出す処理全体**。1 回の質問の裏側で何が起きているか |
| **#3** | **人とエージェント、エージェントの 2 つの作りを比較**。品質・時間・費用から、どの仕事をどの作りで任せるかを選ぶ |

## 登場するもの

```
              あなたが操作する場所
   ┌────────────────┬────────────────┬──────────────────┐
   │ #1             │ #2             │ #3               │
   │ BigQuery Agents│ 教材の Web 画面 │ まとめて質問     │
   │  （Console）   │（Cloud Shell） │ （Cloud Shell）  │
   │ 1 問ずつ質問    │ 1 回実行        │ 3 問×2 通りを一括 │
   └───────┬────────┴───────┬────────┴────────┬─────────┘
           │                │                 │
           │                └────────┬────────┘
           │                         │ 呼び出す
           │                         ▼
           │                  ┌─────────────┐
           │                  │ Root Agent  │ 回答を作る／根拠を確認する
           │                  └──────┬──────┘
           │                         │ 分析を頼む
           ▼                         ▼
        ┌────────────────────────────────┐
        │      Data Agent（①②③）      │  ← 分析する人
        └───────┬───────────────┬────────┘
                ▲               │ SQL を実行
    教材コードが │               ▼
    取得して渡す │         ┌───────────┐
    （②③のみ） │         │ BigQuery  │  5 テーブル・View
   ┌────────────┴──────┐  └───────────┘
   │ Knowledge Catalog │  業務定義（OKF 形式）
   └───────────────────┘

   結果を見る場所
     #1：回答・生成 SQL（Console）
     #2：Cloud Trace（処理の流れ）／BigQuery ジョブ履歴（実行 SQL）
     #3：教材の Web 画面で比較 ＋ 代表実行を Cloud Trace・ジョブ履歴で確認
```

> **#1 は①②③の 3 つの Data Agent を比べます。#2・#3 で Root Agent が分析を頼む相手は③だけです。** ①②は #1 で比べるためだけに使います。①は業務定義なし、②は業務定義あり、③は業務定義あり＋集計 View です。
>
> **業務定義は、Data Agent が自分で Catalog を検索しているわけではありません。** 教材のコマンドが Knowledge Catalog から取得し、②③の用語集へ渡しています。

## #1 のあと、なぜ #2 で別の画面が要るのか

#1 では **BigQuery Agents の会話画面**から Data Agent へ直接質問しました。分析 Agent 単体の振る舞いを見るには、これがいちばん素直だからです。

ただし業務で使うときは、Agent を**アプリから呼び出す**ことになります。回答をそのまま返すのではなく、根拠を確認し、記録を残し、失敗に備える。その役を **Root Agent** が担います。

**#2 で教材の Web 画面を使うのは、この「呼び出す側」を観測するためです。** Console の会話画面からは、Root Agent が内部で何回分析を頼んだか、どこで時間を使ったかが見えません。

| | #1 | #2 | #3 |
|---|---|---|---|
| 操作する場所 | BigQuery Agents（Console） | 教材の Web 画面（Cloud Shell） | Cloud Shell のコマンドで 6 回まとめて質問し、教材の比べる画面で比較 |
| 裏で動くもの | Data Agent | **Root Agent** → Data Agent | 同じ Root Agent を、Data Agent に頼む回数（2 回／1 回）を変えて比べる |
| 結果を見る場所 | 回答・生成 SQL（Console） | Cloud Trace・BigQuery ジョブ履歴 | 代表の 1 件は Cloud Trace（Console）、全体は教材の比べる画面 |

## #3 から参加する方へ

#1・#2 に参加していなくても #3 は進められます。知っておくことは 2 つです。

1. **業務定義**（#1 の題材）：実習を始める前に、Checkpoint で #1 の完成状態を自分の環境に用意します。具体的には、教材のデータ、業務定義、その定義を渡したエージェント③です。業務定義とは「返金をどの月に計上するか」といった会社の取り決めのことで、これがないと同じ質問でも答えが変わります。
2. **Root Agent**（#2 の題材）は、質問を受けて Data Agent に分析を頼み、回答文を書く AI です。#2 では、同じ分析を Data Agent に **2 回**頼む無駄を記録から見つけました。#3 では、この作りと、**1 回**だけ頼んで結果を使い回す作りを比べます。

**#3 の基本課題は、質問を 1 問ずつ手で送るのではありません。** Cloud Shell のコマンドで 3 問 × 2 つのやり方（合計 6 回）をまとめて送り、代表の 1 件を Cloud Trace でたどり、全体を教材の比べる画面で比べます。さらに、分析担当の人が答える場合とも比べます。

詳しくは[実習 3 の「この回で決めること」](lab3.md#この回で決めること)にあります。

## 用語

| 用語 | 意味 |
|---|---|
| **Data Agent** | BigQuery のデータを分析して答える Agent。#1 で①②③に直接質問する。#2・#3 の基本課題では③を使う |
| **Root Agent** | Data Agent を呼び出し、回答をまとめ、根拠を確認する側。#2・#3 の観測対象 |
| **Knowledge Catalog** | 業務定義を管理する場所。#1 で参加者が編集する |
| **OKF** | 業務定義を書く形式。見出し（種類・題名・説明）と本文からなる |
| **Trace / Span** | 処理の流れの記録と、その一つひとつの区間 |
| **評価計画** | #3 で作る、どの質問をどのやり方で何回試すかの計画 |
