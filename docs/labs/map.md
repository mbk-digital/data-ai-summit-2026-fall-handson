# 事前イベントの地図：どこを操作し、何を確かめるか

同じ架空 EC 企業のデータを使い、実習 1 では数字の根拠、実習 2 では回答までの処理を確かめます。

| | 実習 1：業務定義を伝える | 実習 2：処理の流れを調べる |
|---|---|---|
| 操作する場所 | BigQuery Agents の会話画面と Knowledge Catalog | Cloud Shell で起動する教材の Web 画面 |
| 裏で動くもの | 分析エージェント①②③ | Root Agent が分析エージェント③を呼ぶ |
| 確認するもの | 回答の数字・集計期間・生成された SQL | 処理の順・依頼の回数・時間・トークン・エラー |
| 記録を見る場所 | BigQuery Agents の回答・SQL | Cloud Trace と BigQuery のジョブ履歴 |

## 業務定義を渡す仕組み

Knowledge Catalog に書いた業務定義を、教材のコマンドが取得し、②③の用語集へ渡します。エージェントが自分で Catalog を検索する仕組みではありません。

①は業務定義なし、②は業務定義あり、③は業務定義あり＋集計 View です。実習 1 で同じ質問への回答を比較します。

## 実習 2 で画面が変わる理由

実習 1 は分析エージェントへ直接質問します。実習 2 は、分析を依頼して回答をまとめるアプリ（Root Agent）を通して質問します。教材の Web 画面で動かし、呼び出す側が何回分析を頼み、どこで時間を使ったかを記録で確かめます。分析を頼む相手は③です。

## 用語

| 用語 | この教材での意味 |
|---|---|
| Data Agent | BigQuery のデータを分析して答えるエージェント |
| Root Agent | 分析を依頼し、根拠を確認して回答をまとめる教材のアプリ |
| Knowledge Catalog | 業務定義を書く・管理する場所 |
| OKF | 教材で業務定義を書く形式。見出しと本文からなる |
| Trace / Span | 処理の流れの記録と、その一つひとつの区間 |

Summit では品質・時間・費用の比較へ進みます。実習 3 の教材は後日公開予定です。
