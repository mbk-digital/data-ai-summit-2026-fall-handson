# ハンズオンを終える：クラウド環境を片付ける

実習で作ったものを使わなくなったら、利用料金がかからないように片付けます。

> [!IMPORTANT]
> Summit にも参加する方や、後日も同じ環境を使う方は、まだ片付けません。[バックアップ](backup.md)を確認してください。

## A．実習専用の Project なら、Project ごと削除する（おすすめ）

このハンズオンのために作った Project なら、Project ごと削除するのがいちばん簡単で、消し忘れもありません。

1. Google Cloud コンソール上部で、削除する Project が選ばれていることを確認します。
2. メニューから「**IAM と管理**」→「**設定**」を開き、「**シャットダウン**」を押します。
3. 表示された Project ID を入力して、削除を確定します。

BigQuery のデータ、Knowledge Catalog のエントリ、エージェント、実行履歴の設定がまとめて削除され、利用料金もかからなくなります。削除から 30 日以内であれば、同じ画面から復元できます。

教材フォルダは、Project を削除しても Cloud Shell に残ります。編集した定義や回答の記録を残したい場合は、そのままにしておきます。

不要になったフォルダを削除する場合は、`participant/` の編集や回答の記録も一緒に消えることに注意してください。削除する前に、そのフォルダがどの Project のものかを確認します。表示された Project ID が、削除した Project と同じであることを確かめてから、フォルダを削除してください。

```sh
grep project_id ~/summit-workshop/config/workshop.local.json
```

## B．Project にほかの用途がある場合は、教材が作ったものだけを削除する

教材フォルダに残っている記録をもとに、教材が作ったものだけを削除します。**この記録が必要なので、片付けが終わるまで教材フォルダを削除しないでください。**

削除する対象を確認します。この段階では何も削除しません。以前の教材を `~/summit-workshop-old` などに移した場合は、片付ける Project の記録が残っているそのフォルダを使います。このページのコマンドにある `~/summit-workshop` も、そのフォルダに置き換えます。

```sh
cd ~/summit-workshop && uv run --locked python3 -m workshop.teardown
```

表示された Project・エージェント・Dataset が今回の教材のものだけであることを確認し、削除する場合だけ次を実行します。

```sh
cd ~/summit-workshop && uv run --locked python3 -m workshop.teardown --execute
```

権限エラーなどで削除できない場合は、表示された対象とエラー文を主催者へ伝えてください。

<details>
<summary>B の削除で行うこと・止まる条件</summary>

- Graph（以前の教材で作った場合だけ）→ Knowledge Catalog → エージェント → BigQuery → AI の実行履歴を残す設定（標準 Observability）の順に削除します。事前の検査で問題があれば、削除を始めません。
- 保存済みの Cloud Trace とメトリクスは削除しません。それぞれの保存期間の設定に従って消えます。
- エージェントは、教材の記録にあり、作成後に変更されていないものだけを削除します。BigQuery は、教材の記録・管理ラベル・データ・テーブル定義・View の SQL を確かめ、記録にないテーブルや変更があれば止まります。Dataset は空になってから削除します。
- 途中で失敗した場合は残りを止め、完了した段階を `artifacts/teardown.json` に保存します。原因を解消して同じコマンドを実行すると、残りを確かめてから再開します。
- Project、`participant/`、回答記録は削除しません。
- 教材フォルダの記録を失った場合は、自動では削除できません。バックアップから戻すか、Cloud コンソールで Project・Dataset・エージェントを個別に確認し、主催者に相談してください。

</details>
