# Data & AI Summit ’26 Fall ハンズオン

本リポジトリは Data & AI Summit ’26 Fall のハンズオン教材です。**2026 年 10 月 26 日の事前イベント（実習 1・2）** と **11 月 18 日の Summit（実習 3）** の教材を公開しています。イベント終了後の継続的な更新は予定していません。

「売上は伸びているのに、なぜ利益が減っている？」を題材に、EC データを分析する AI エージェントを改善するハンズオンです。実際に質問し、回答の根拠・処理の流れ・費用を確認しながら、業務で使うための判断を練習します。

架空の EC 企業のデータを使うため、自社データの用意や、ローカル PC への Python インストールは不要です。基本課題では SQL を自分で書く必要はありません。Cloud Shell で準備や評価のコマンドを実行し、クラウドや教材の画面で質問・定義編集・結果確認を行います。さらに試したい方には、各実習の手順書に任意の発展課題（Challenge）を用意しています。

## このハンズオンで学ぶこと

| 実習 | 試すこと | 持ち帰る視点 |
|---|---|---|
| **1．業務定義を伝える**（Semantics） | 「売上」「返金」の扱いを定義し、同じ質問への回答を比較する | 正しい数字を得るために、どんな前提を共有する必要があるか |
| **2．処理の流れを調べる**（Observability） | 1 回の質問の裏側を Trace でたどる | 何がどの順で起き、どこで時間とトークンを使ったか説明できるか |
| **3．品質・時間・費用を比べる**（Economics） | 同じ質問に、分析担当の人が答える場合と、AI エージェントが答える場合を比べる。AI エージェントは、分析を毎回取得する作りと、取得した分析を再利用する作りの 2 通りを試す | 品質・時間・費用のトレードオフを見て、場面ごとにどの作りを選ぶか説明できるか |

どこを操作し、裏で何が動き、どこで結果を見るかは[全体の地図](docs/labs/map.md)にまとめています。

## 1．教材を取得する

用意するものは、ブラウザ、Google Cloud アカウント、参加者自身の個人用 Google Cloud プロジェクトとその**オーナー権限**（自分で作成したプロジェクトなら付与済み）です。実習では Gemini などの有料サービスを利用するため、**利用料金が発生します**。実際の請求額は無料枠やクレジットの適用状況によって異なります（イベント参加時は主催者の案内を確認してください）。

Google Cloud のブラウザ内ターミナル **Cloud Shell** を開き、次を実行して教材を取得します。

```sh
git clone --branch main https://github.com/mbk-digital/data-ai-summit-2026-fall-handson.git summit-workshop
```

> Cloud Shell のホームフォルダは、Project ごとではなく Google アカウントごとに 1 つです。Project を切り替えても、以前に取得した教材フォルダと、その中の設定（対象の Project など）は残ります。

<details>
<summary>エラーが出た場合</summary>

- `Username` を求められた、または `Repository not found` と表示された：URL がこのページの公開リポジトリと一致するか確認してください。教材の取得に GitHub アカウントは不要です。解消しなければスタッフに相談してください。
- `fatal: destination path 'summit-workshop' already exists` と表示された：この Cloud Shell に以前取得した教材が残っています。
  - **以前と同じ Project で続ける場合**：[教材を更新する](docs/cloud-shell-workflow.md#教材を更新する)の手順で最新にしてから、下の 2 へ進みます。
  - **新しい Project で最初からやり直す場合**：残っている教材フォルダの名前を変えてから、もう一度上の `git clone` を実行します。元のフォルダは消さずに残します。前の Project を片付けるときに必要になるためです。

    ```sh
    mv ~/summit-workshop ~/summit-workshop-old
    ```

</details>

取得できたら、教材フォルダへ移動します。

```sh
cd summit-workshop
```

そのほか取得で困った場合は[詳しい取得手順](docs/cloud-shell-workflow.md#初めて教材を取得する)を確認してください。

## 2．参加する回の手順を進める

自分が参加する回の表を、上から順に進めます。手順書や画面の「#1」「#2」「#3」は実習番号です。

### 事前イベントに参加する方

当日の時間配分は[当日の流れ・時間割](docs/labs/pre-event.md)を参照してください。

| 順番 | 開くページ | ここまでできたら次へ |
|---|---|---|
| 環境の準備 | [共通の事前準備](docs/labs/preparation.md) | BigQuery Console で 5 テーブルと View、BigQuery Agents の Monitoring を確認した |
| 実習 1 | [業務定義を伝える](docs/labs/lab1.md) | Knowledge Catalog で定義を編集し、BigQuery Agents で 3 つの Agent の回答と SQL を比較した |
| 実習 2 | [処理の流れを調べる](docs/labs/lab2.md) | Cloud Trace と BigQuery ジョブで、処理の順・時間・トークン・エラーを確認した |

終わったら、このページの「3．実習を終える」へ進みます。

### Data & AI Summit に参加する方

当日の時間配分は[当日の流れ・時間割](docs/labs/summit.md)を参照してください。

| 順番 | 開くページ | ここまでできたら次へ |
|---|---|---|
| 準備（初参加の方） | ① [共通の事前準備](docs/labs/preparation.md) ② [Summit の開始確認](docs/labs/checkpoint.md) | 開始確認で「開始できます。」と表示された（完成した定義と Agent はこのとき作られます。数分かかります） |
| 準備（事前イベントに参加した方） | ① [教材の更新手順](docs/cloud-shell-workflow.md#教材を更新する) ② [Summit の開始確認](docs/labs/checkpoint.md) | 主催者の案内に沿って教材を Summit 用の版に更新し、開始確認で「開始できます。」と表示された |
| 実習 3 | [AI エージェントに任せると、何が変わるか](docs/labs/lab3.md) | 2 つの場面で、人・AI エージェント（毎回取得・再利用）のどれを選ぶかと、その理由を書いた |

準備は、できれば当日より前に済ませてください。当日より前に済ませた方は、当日の最初に[開始確認](docs/labs/checkpoint.md)をもう一度実行します（環境がまだ使えるかを確かめます。1 分ほどで終わり、環境に変更がなければ何も作りません）。当日その場で準備した方は、もう一度実行せずに実習 3 へ進みます。

事前イベントに参加していなくても、Summit から参加できます。当日は、実習 1・2 の内容を短く振り返ってから実習 3 へ進みます。時間をかけて操作から理解したい方は、事前に上の「事前イベントに参加する方」の表の実習 1・2 も体験できます（任意）。進めた場合も、最後に [Summit の開始確認](docs/labs/checkpoint.md)を実行します。事前イベントで投影した[説明資料（スライド）](https://docs.google.com/presentation/d/1u_TbciboQ0xSoQ0SB4UqgTuiMItl4Iq-Ru2t3Ep4KtA/edit?usp=sharing)も公開しています。

## 3．実習を終える

どちらか一方を行います。

- **後日も同じ環境を使う方**（事前イベントの後、Data & AI Summit にも参加する方など）：[バックアップ手順](docs/labs/checkpoint.md#手順-3バックアップを残す環境を後日も使う方)に沿って設定と管理台帳を保存します。Summit より前に、上の「[Data & AI Summit に参加する方](#data--ai-summit-に参加する方)」の表の「準備（事前イベントに参加した方）」の行を済ませます。当日は、最初に開始確認をもう一度実行してから実習 3 へ進みます。
- **今後使わない方**：[片付け手順](docs/labs/cleanup.md)に沿ってクラウド環境を削除します。実習専用の Project なら、Project ごと削除するのがいちばん簡単です。

[教材の更新・再開手順](docs/cloud-shell-workflow.md)と、各ページのトラブル時の説明（[事前準備](docs/labs/preparation.md#途中で止まったら)・[実習 1](docs/labs/lab1.md#再開トラブル時)・[実習 2](docs/labs/lab2.md#うまくいかないとき再開)・[Summit の開始確認](docs/labs/checkpoint.md#手順-4止まったとき)・[実習 3](docs/labs/lab3.md#困ったとき)）を確認してください。

解消しなければ、読んでいる手順・実行したコマンド・エラー文を主催者の案内した窓口へ連絡してください。認証トークンや秘密鍵は送らないでください。
